# 使用场景

## 多服务工作区目录

由消费方发现根目录解决方案清单，合并并去重其中的工作区内 C# 项目，应用仓库自己的排除规则，再一次性提交最终项目列表。持久化结果时同时保存 `ProjectUnitSourceAnalysisContract.Version`，契约版本变化时应使缓存失效。

## Agent 就绪度覆盖率

把显式元数据、描述、负责人和需求 ID 作为彼此独立的维度。需求是否存在属于消费方职责：语义分析完成后，再到工作区知识系统解析 ID。如果目标不存在，仅有源码注解不能证明追踪关系成立。

## 安全刷新

对选定项目集、Git 状态、相关源码内容和外部追踪输入计算指纹。只保存成功或部分目录；刷新失败或取消时，应保留上一个持久化快照。

## 常见错误

- 未先应用仓库策略就提交测试项目或外部项目。
- 把 `IsPartial` 当作完整覆盖率。
- 在跨项目工作区中使用 `RuntimeKey`，而不是 `CatalogKey`。
- 未检查知识库目标是否存在，就把带需求注解的单元视为已解析。
