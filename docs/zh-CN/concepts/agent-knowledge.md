Monica 的实现与行为测试决定框架实际如何工作。Agent Skill 说明在具体任务中如何使用这些行为；本站则提供稳定的概念与采用指南。明确分工后，代码变更可以修正对应指导，而不必维护另一份手写 API 参考。

## 指导内容放在哪里

规范 Skill 位于 Monica 仓库的 `skills/<name>/`。简短的 `SKILL.md` 负责把 Agent 引向正确任务；`references/` 按需展开配置、示例、失败语义以及源码和测试依据。普通应用任务应能依靠这些参考完成；实现框架、核实版本敏感细节或调查疑似缺陷时，再查看精确源码。

九个 `monica-infra-*` Skill 分别负责**宿主**、**持久化**、**消息通信**、**作业**、**配置**、**可观测性**、**AI**、**Web** 与 **UI** 的使用指导。它们按开发者要完成的工作组织相关模块。可以在[能力 Skill 列表](/zh-CN/skills)中选择能力；[Agent 索引](/llms.txt)列出相同的已发布 Skill 和原始 Markdown 资源。

Monica.Docs 负责稳定的双语概念与指南，包括本页。网站上的 Skill 页面、原始 Markdown 路由和 `llms.txt` 都是 Monica 规范 Skill 内容的确定性只读投影。公开构建使用与框架版本匹配、来自干净发布标签的不可变知识产物，并校验摘要。本地预览可以展示当前 Monica 源码，但会明确标记为预览。技术指导发生变化时编辑 Monica 中的规范 Skill；面向人的稳定解释发生变化时编辑 Docs 指南。

Monica.Guide 安装框架拥有的 Skill，也可定位经过验证的 Monica 框架源码检出。它不为 Monica.Docs 设置专用贡献者 Profile 或源码绑定。编写本站内容时，直接使用当前 Docs 检出。

## 让验证结果回到知识源

实现变更或用户反馈暴露指导缺口时，先依据相关源码和测试复现、核实行为，再替换或整合归属 Skill 的参考内容，写入经验证的规则和精简示例。契约需要保护时，增加或更新行为检查。不要把会话笔记不断累积为永久规则，也不要在证据不足时把一次局部事件升格为通用约束。

发布前重新生成并校验已安装 Skill 投影和网站知识导出。Monica 随不可变框架版本发布这些知识，让读者能够识别收到的精确源码与内容。

基础设施源码的 Pull Request 应在 Monica 仓库运行归属检查：

```bash
python scripts/check_knowledge_impact.py --base <base-ref>
```

目录中的 `sourcePaths` 会把变更的实现文件映射到最具体的 Skill 归属方。检查会报告对应规范 `SKILL.md` 或参考文件是否更新。如果核实后确认行为和使用指导没有受到影响，应使用 `--no-impact "原因"` 明确记录理由；这是供评审的判断，不是新增的知识页面。
